# Замер качества: мутационное тестирование ревьюера

Файл сформирован командой `npm run eval`. В два чистых ТЗ (`eval/specs/`) по одному вносятся известные дефекты; дефект считается найденным, если агент сообщил о мутанте то, чего не сообщал о чистом тексте. Документ хакатона в эталон не входит: правила под него не подгонялись.

Версия агента: 0.1.0 (319f997b90; отпечаток исходников ed4e5a368772). Модель: claude-sonnet-5-5 (claude-cli); для экономии запросов выполнялись этапы набора, оппонент и проверка критериев приёмки, без этапа вопросов.

Как считается «найдено». Слой правил детерминирован, поэтому любое новое замечание на мутанте вызвано мутацией. Для модели требуется больше: замечание должно цитировать изменённое место текстом, которого нет в чистом документе, либо — для удалений — называть требование, оставшееся без покрытия, чаще, чем на чистом документе.

Что замер не показывает. Правила разрабатывались с оглядкой на этот набор мутаторов, поэтому полнота правил — нижняя граница для документов в том же шаблоне, а не оценка на произвольном ТЗ. Чистые ТЗ написаны для замера и вычитаны только на дефекты, которые ловят правила; модель находит в них собственные пропуски, часть которых реальна. Поэтому число замечаний модели на чистых документах — не мера её ложных срабатываний: такой меры здесь нет.
