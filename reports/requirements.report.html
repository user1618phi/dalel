Вопросы автору

  1. Q-01блокирует разработкуриск высокий · клиент

    По какой метке времени операция попадает в расходы и относится к месяцу в часовом поясе Алматы (UTC+5)?

    Кому
    владелец продукта
    Почему важно
    Ф-2 и критерий приёмки задают разные месяцы для одной покупки. Без ответа push уйдёт не в тот месяц или не уйдёт совсем, приёмка не пройдёт ни при одной реализации, а у запоздавших событий не будет правила для закрытого месяца.
    Риск
    Ошибка месяца даёт ложный или пропущенный push именно на границе месяца, а приёмка при этом блокируется.
    Варианты и последствия
    • По авторизации: расходы растут при авторизации, месяц — по дате авторизации Цель «в момент покупки» выполняется. Критерий приёмки переписывается на январь. В Ф-2 добавляется уменьшение расходов при реверсале. Событие авторизации нужно получать из процессинга.
    • По проведению: расходы растут при проведении, месяц — по дате проведения Критерий приёмки остаётся как есть. В Ф-2 «дата совершения» меняется на «дата проведения». Цель переформулируется: push приходит после проведения покупки. Запоздавших событий за закрытый месяц не бывает.
    • Учёт по событию проведения, месяц — по дате авторизации Ф-2 остаётся как есть, критерий приёмки исправляется на январь. Нужно отдельное правило для push по закрытому месяцу, если его довела до порога покупка, проведённая уже в следующем месяце.
    Ситуация
    Покупку на 4 000 ₸ совершили 31 января в 23:58, а провели 1 февраля в 00:03 по Алматы. По Ф-2 она январская, по критерию приёмки — февральская.
    Рекомендация агента

    Если ответа не будет
    Любая ошибка проверки параметров возвращает 400, код 200 — только с result OK.

    Кому
    владелец продукта
    Почему важно
    Ф-3 и Ф-4 нельзя выполнить одновременно. Разработчик выберет одно из них сам, и клиент либо не узнает о новом бюджете, либо получит повторные уведомления.

    Клиент, который поднял бюджет, не узнает о его достижении или будет получать повторные push при каждом сохранении.
    Варианты и последствия
    • Да: новое значение порога сбрасывает признак отправки Ф-3 уточняется: один push на одно значение порога в месяц. Повторное сохранение той же суммы и переключение без смены суммы признак не сбрасывают. Если новый порог не выше накопленной суммы, перехода снизу нет и push не уходит.

    Рекомендация агента
    Да: новое значение порога сбрасывает признак отправки — Ф-4 прямо требует push после смены порога, Ф-3 защищает от повторов, и вариант 1 сохраняет смысл обоих пунктов.
    Если ответа не будет
    Строго один push на карту за календарный месяц, смена порога его не сбрасывает.
